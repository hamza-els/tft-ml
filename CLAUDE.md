# TFT ML project

Offline advisor for Teamfight Tactics: read game state out of stream VODs,
then learn what strong players do. It must never click in a live game (Riot
Vanguard would ban the account).

Owner: Hamza. He labels data and makes the design calls; explain results in
plain language and say plainly what was and wasn't verified.

## Pipeline, in order

```
python scripts/process_vods.py --urls FILE        # all of the below, one VOD at a time (preferred)

python scripts/run_pipeline.py                    # urls in data/raw/urls.txt: download, extract, split games, dedup
python scripts/extract_states.py --frames ~/tft_frames_temp/VOD   # OCR etc. -> ~/tft_data/state_vectors/VOD/game_XX.jsonl
python scripts/read_units.py     --frames ~/tft_frames_temp/VOD --states ~/tft_data/state_vectors/VOD   # board/bench units -> units_raw (re-run after retraining)
python scripts/clean_states.py   --states ~/tft_data/state_vectors/VOD   # -> game_XX.clean.jsonl (incl. cleaned board/bench) + quality report
python scripts/build_dataset.py  --states ~/tft_data/state_vectors/VOD   # -> ~/tft_data/datasets/states/VOD/game_XX.npz
python scripts/upload_states.py VOD               # copy the finished state files into the repo
```

## Things that will bite you

- **Everything is calibrated to one HUD layout**: BoxBox's stream, VOD `knB6dE8Rbgg`, TFT Set 18. Regions in `configs/vision_config.yaml`, `WATCH_REGIONS` in `frame_dedup.py`, and the templates in `assets/templates/hud/` are all specific to it. Another streamer or UI scale gives silent garbage or "no games detected". Run `preview_regions.py` before processing anything new.
- **A new TFT set** needs `fetch_game_data.py --set ...`, new icon templates, and changes the state vector's size (champion and trait counts).
- **The HUD is always the player's own, the board is not.** About 28% of frames show another player's board (away fights, scouting). `home_board` marks own-board frames: the augment bar on the left only means own board, on the right only means someone else's (scouting). **In combat both bars show** (board owner's on the left, visitor's on the right), so then, and with no bar, the arena colour decides (`home_board_rows`). Never read units or augments off a frame that isn't `home_board`.
- **The augment bar's count must be known before cutting icons**: cutting 2 icons as 3 gives crops straddling two icons (Hamza found many in the labeler, 2026-11-19). `AugmentReader` (`src/vision/augments.py`) tries every count the stage allows (`expected_counts`: at least the picks done, 2-1/3-2/4-2; up to 4: a 4th augment shows up in some games, and extras are common, e.g. 3 at 3-2) at every centre within ±20 px of the calibrated one (8vvYT3TbJTw sits ~15 px right; another player's bar moves with the camera), and keeps the best fit: dark outline inside, scenery just outside, icons centred in their slots, every slot with an icon over several middle rows. Dark scenery (vzUwGQ4GxFQ's forest) leaves only the icons' centring to decide; a dark panel sliding over the bar (only icon tops show) reads 0. Checked by eye on 96 random bars across all 8 VODs: 93 cut right, the rest a bar mid-animation or under the XP bar. The old reader missed most other-player bars (403 of 2,280 sampled frames now found).
- **BoxBox's overlay lists each game's augments by name** (bottom left, under "Portal: ..."; `src/vision/augment_overlay.py`). It is typed by his team: typos ("Healing Obs II"), guesses ("Golden Gala (probably)"), and a sponsor pop-up covers it now and then, so a game is read on 25 frames after 4-2 and voted. OCR loses commas and reads "+" as "t", so names are found by covering the words in order with the set's 367 names. Against Hamza's labels (90 games, 2026-11-20): same order as the bar in 82 of 88 games read; 88% of 291 slots the same augment in the same slot, 91% anywhere; 17 of the 35 misses are names the vote dropped. The augment-only frame copies black it out, so it must be read before slimming. Cleaning uses label > overlay > icons and adds `portal` and `augment_source` to each cleaned row.
- **Some augments share one icon in the game** (crops 0.99 alike, and the overlay itself uses both names), though the official art differs: merged in `aliases.json`, kept name first: Spreading Roots / Max Build, Team Building / Pandora's Bench, Challenger's Grace / Trifecta I, Pandora's Items II / Solo Plate, Nesting Anvils / Living Forge, Commerce Core / Shopping Spree (Hamza's word; no game shows it yet). Caretaker's Ally (1 labelled game, no overlay) looked like Patient Study and Woven Magic: probably a label slip. Same icon at another tier stays apart by tier: Silver / Gold / Prismatic Destiny, Ascension / Partial Ascension, Glass Cannon I / II, Healing Orbs I / II, Band of Thieves I / II. `GameData.augment_base` strips every trailing "+" then the tier numeral (one "+" only, before 2026-11-20).
- **Planning vs combat** comes from the round timer bar refilling (`planning_rows` in `src/vision/arena.py`), plus: no enemy bars on the far half, timer not empty, and no "Combat" banner under the stage bar (`combat_banner`, greyscale template of the word; a "Planning" banner sits at the same spot and scores 0.5-0.6 against it, "Combat" 0.6-1.0). Frames at combat start show units turned to face the enemy, which confused the classifier. Units are only read in planning; Hamza decided mid-combat unit data is not needed.
- **The streamer often hides the shop bar**, so "gold icon missing" does not mean carousel. Bottom-bar values are `None` then, not guessed.
- **The stage bar shifts right during stage 1**; stage text is read relative to the detected icon.
- **HP can rise and exceed 100** (augments). Two panels can replace the player list: the "Damage Dealt" recap (own HP still shown at the top) and a unit info panel (no HP).
- **State reading skips OCR of unchanged regions** (`OcrCache` in `ocr_pipeline.py`): a region is re-read only when its bright text pixels changed, and a value is reused only after two reads agreed. HP is read once per round (until two own-HP reads agree and the lobby list was read): the HP column changes on almost every frame (notices sliding over names, animated portrait rings), so it can't be change-gated. Consequence: between a fight ending and the next round's counter, `hp` still shows the pre-fight value; lobby HP is the round-start value. Checked on 300 frames: 66% of OCR skipped, stage/level/XP/streak/shop identical to per-frame reading, gold differed on 2 frames (an OCR misread both versions share).
- **Google Drive locks files while syncing**: a rename in `extract_states.py` failed with WinError 32 and lost a VOD's run; it now retries. Other writers may need the same if it recurs.
- **Dedup deletes frames permanently.** Split into games before dedup. Hovering a shop card opens a tooltip that covers half the bench.
- **Stopping a batch mid-extraction** used to leave a folder that `run_pipeline.py` took for fully extracted (its rule for folders from before `.pipeline_steps` existed), so it split ~200 frames, found no games and failed (SZZrxLQq_gI, 2026-11-19). The rule now only applies to folders without `.pipeline_steps`. Stop batches between VODs if you can; kill the whole tree (`taskkill /PID <process_vods pid> /T /F`) otherwise.
- **Windows shell quirks:** set `PYTHONIOENCODING=utf-8` when piping script output (box-drawing characters crash cp1252). Long bash heredocs with apostrophes have failed; write a patch script to the scratchpad instead. Don't run two jobs that rewrite the same `game_XX.jsonl` at once.
- **Several Claude sessions may work on this repo at once** (2026-11-19: one ran a 20-VOD batch while another re-read augments). Before rewriting state files or deleting frames, check running jobs (`Get-Process python*` and their command lines) and other sessions (ListAgents), and say what you're about to touch. The batch calls each step script fresh per VOD, so an edit to a step script reaches a running batch's next VOD: keep such edits backward compatible.
- **RAM is 15.6 GB.** Every process that loads EasyOCR/torch takes 1-2 GB, and `--jobs 3` means three of them. On 2026-11-19 a batch plus 3 augment re-reads plus 3-worker benchmarks ran it out: one game's item step took 3 h instead of ~1 min, and two jobs died with cv2 "Insufficient memory". While a batch runs, run other heavy jobs one at a time. **The page file is on C: too**: with ~20 GB free, R26Tm0lwhnA's state reading died loading torch with "WinError 1455: The paging file is too small" (2026-11-19). Low disk means low memory.
- **Back-to-back games** (a new game found from the stage-1 layout with no gap) used to get overlapping frame ranges in `find_game_segments` (each padded by one scan step), so one frame was moved twice and the split crashed (wszJroIjlMs, 2026-11-19, before dedup: nothing lost; frames moved back to the top folder and re-split). Ranges are now clipped at the midpoint between games.
- **numpy matrix products get ~90x slower once torch is imported** (0.6 ms -> 56 ms for 180x3366 @ 3366x25; the two thread pools fight). `OMP_NUM_THREADS=1` before import fixes the product (4 ms) but an end-to-end test of `extract_states.py` was inconclusive under load, so it isn't set. Prefer torch ops, or few big products, in hot loops.
- **Dedup** (`frame_dedup.py`, called with `combat_aware=True, watch_board=True`): compares per cell (`CELLS`), not whole regions; in combat the bench is not watched (gold or shop changing triggers a bench re-check); in planning the board is watched, with at least 2 s between board-triggered saves (Hamza: finicky unit dragging shouldn't count as important, but redundant board frames help when units are covered).
- **yt-dlp** needs to be recent and needs `--js-runtimes node` (already in `run_pipeline.py`), or YouTube returns 403 mid-download. Run it as `python -m yt_dlp` (no `yt-dlp` on PATH). ffmpeg can't read YouTube's direct https stream URLs (403 even with yt-dlp's headers), and seeking in the HLS playlist with ffmpeg times out; fetching one HLS segment plus the playlist's `EXT-X-MAP` init segment works (`sample_vods.py`).
- **Not every TFT-looking stream is his own game.** Watch parties and some bootcamp days (bCWxl3ZbkuU, mIBT_GF3VOY, mmODH100r1Q, probably dyVQ5ZQI7tQ) spend hours spectating other players: a full TFT HUD with someone else's webcam or a name/avatar top left. The stage icon is found there too, so the pipeline would take them as BoxBox's games. Bash tournament days are skipped for the same reason. Many 18.3-18.6 streams are TFT then Fire Emblem / Deadlock / Arkheron; the title alone doesn't tell the share.

## Decisions already made (don't reopen without reason)

- Champion classes are names only, no star level in the label. Star level is read separately later.
- The shop is read by OCR of card names, not by a detector.
- Board and bench units are found by their health bar (`unit_reader.occupied`: a green bar lined up with the hex/slot with a star badge on its left; the badge rules out the Little Legend's nameplate bar), cut with a window anchored to that bar (`board.anchored`: fixed size, centred on the bar, top just above the badge), then classified. Hamza chose anchored windows over fixed ones (2026-11-18): held-out accuracy went from 91.5% to 93.7%. The YOLO path (`train_yolo.py`, `champion_detector.py`, `data/processed/labeled/`) predates this and is probably unnecessary.
- Other players' boards are ignored. Scouting is not modelled.
- Augment and item icons are matched to templates cut from footage and identified by ID (`aug_007`, `item_031`). Names are optional: the model only needs consistent IDs.
- No hard-coded thresholds in the decision logic; the Win Predictor's output is to be a model input.

- Split multi-action transitions instead of dropping them as UNKNOWN.
